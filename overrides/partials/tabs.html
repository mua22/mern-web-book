That distinction matters: nesting several multi-page books under one real nav parent makes Material's navigation.sections render ALL of that parent's siblings' full page trees stacked together in the primary sidebar whenever you're on ANY one of them, since "sections" shows the active top-level tab's whole subtree. Keeping them as separate top-level entries restores correct per-book sidebar scoping, so this file fakes the grouping only at the tab-bar level by intercepting known titles as tabs.html's own loop reaches them, using tabs-item.html's first_leaf_url/render_submenu_link helpers to link into each book normally.

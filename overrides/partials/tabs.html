{#- Override of material/templates/partials/tabs.html. Groups top-level nav entries into named dropdowns (currently "Courses" and "Labs") purely for the top nav bar display -- mkdocs.yml keeps each course/lab-book as its OWN top-level nav entry, never nested under a shared "Courses"/"Labs" parent. That distinction matters: nesting several multi-page books under one real nav parent makes Material's navigation.sections render ALL of that parent's siblings' full page trees stacked together in the primary sidebar whenever you're on ANY one of them, since "sections" shows the active top-level tab's whole subtree. Keeping them as separate top-level entries restores correct per-book sidebar scoping, so this file fakes the grouping only at the tab-bar level by intercepting known titles as tabs.html's own loop reaches them, using tabs-item.html's first_leaf_url/render_submenu_link helpers to link into each book normally. Adding a new grouped book later (another course, another labs book): add its exact nav title to the matching group's `titles` list below, and keep it as its own top-level entry in mkdocs.yml -- nothing else in this file needs to change. A group can also name a `landing_title`: a top-level nav entry (a single standalone page, e.g. "Courses" -> courses.md) whose own URL becomes the dropdown tab's instead of the default fallback (the first course's first leaf page). That entry must appear in mkdocs.yml's nav BEFORE the group's own titled entries, so its URL is captured before the dropdown is first rendered. The landing entry is never rendered as its own separate tab -- it's absorbed into the group entirely, only supplying the dropdown's link target (and, if the landing page itself is the active page, the tab's active state).
